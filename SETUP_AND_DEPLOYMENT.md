# My Platform — Setup & Deployment Guide

This guide is written for the workflow requested for this project:

**Phone/browser only → GitHub website → Netlify deployment → Firebase + Cloudinary configuration.**

No Codespaces or local laptop workflow is required.

---

## 1. What you are deploying

The project is a Next.js 16 application with:

- public personal-brand website;
- portfolio;
- blog and CMS;
- contact form;
- newsletter;
- CRM lead tracker;
- project pipeline;
- analytics;
- finance tracker;
- content calendar;
- file manager;
- site settings/control panel;
- Firebase Auth + Firestore;
- Cloudinary media storage;
- optional Resend email sending.

The abandoned real-estate AI property-video service is not part of the site.

---

## 2. Create the GitHub repository

On GitHub:

1. Create a new empty repository.
2. Give it any repository name you like.
3. Keep it empty for the upload step; you do not need a README generated by GitHub because this project already contains one.
4. Open the repository's **Add file → Upload files** flow.
5. Upload the contents of this project so that `package.json` is at the repository root.
6. Commit the files to the default branch.

Important: do **not** upload any real `.env.local` file or Firebase service-account JSON file.

---

## 3. Create the Firebase project

Open the Firebase Console and create a new project.

You do not need Firebase Storage for this version of the site.

### 3.1 Register a web application

Inside the Firebase project:

1. Open **Project settings**.
2. Add a Web App.
3. Copy the Firebase web configuration values into the Netlify variables later.

You will need:

- `NEXT_PUBLIC_FIREBASE_API_KEY`
- `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN`
- `NEXT_PUBLIC_FIREBASE_PROJECT_ID`
- `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET`
- `NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID`
- `NEXT_PUBLIC_FIREBASE_APP_ID`

`NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET` is kept because it is part of standard Firebase web configuration, even though application media uploads use Cloudinary.

### 3.2 Enable Authentication

Open **Authentication → Sign-in method** and enable:

- Email/Password
- Google

For Google sign-in, use the Firebase-provided auth domain/configuration.

### 3.3 Add your deployment domain to Auth settings

After you know your Netlify hostname, add that hostname under Firebase Authentication's authorized domains.

Also add your final custom domain once you connect one.

Examples:

- `your-project.netlify.app`
- `www.yourdomain.com`
- `yourdomain.com`

Do not add protocol prefixes such as `https://`.

### 3.4 Create Firestore

Open **Firestore Database** and create the database.

This project uses Firestore as the application database.

### 3.5 Add Firestore rules

The repository contains:

`firestore.rules`

You can paste its contents into the Firebase console Rules editor.

The application primarily performs its important mutations through Firebase Admin on the server. The rules still protect direct client-side access and require the `admin` custom claim for privileged operations.

### 3.6 Indexes

The repository contains:

`firestore.indexes.json`

The current application does not depend heavily on complex client-side composite queries, but the file is included so the intended indexes are documented and ready for future Firebase CLI deployment.

## 4. Create Firebase Admin credentials

The server needs Firebase Admin credentials to verify sessions and access Firestore securely.

### 4.1 Create a service account

In Google Cloud Console:

1. Open **IAM & Admin → Service Accounts**.
2. Select the Firebase/Google Cloud project.
3. Create a service account for the application.
4. Create a JSON key for that service account.
5. Download it temporarily somewhere safe.

You do **not** upload the JSON file to GitHub.

From the JSON you need:

- `client_email`
- `private_key`
- the Firebase project ID.

The project already knows the project ID through `NEXT_PUBLIC_FIREBASE_PROJECT_ID`.

### 4.2 Netlify variables

Set:

```text
FIREBASE_CLIENT_EMAIL=<service account client_email>
FIREBASE_PRIVATE_KEY=<service account private_key>
```

For `FIREBASE_PRIVATE_KEY`, preserve the escaped `\n` line breaks from the JSON string when pasting into Netlify.

---

## 5. Create the first admin account

The project does **not** make the first Firebase user an admin.

Instead:

1. Choose the exact email address you want to use as the site administrator.
2. Create that account in Firebase Authentication.
3. Set the same email as:

```text
ADMIN_EMAIL=your-real-admin-email@example.com
```

4. Sign in through `/login` after deployment.
5. The server will recognize the exact email and establish the admin authorization claim/session.

The admin email is intentionally a server-side environment variable and is not exposed through the public settings API.

---

## 6. Create the Cloudinary account

This project uses Cloudinary instead of Firebase Storage for application media.

Create a Cloudinary account and retrieve:

- cloud name;
- API key;
- API secret.

No unsigned upload preset is required for the application's file manager because the implementation uses signed uploads generated on the server.

Netlify variables:

```text
NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME=
CLOUDINARY_API_KEY=
CLOUDINARY_API_SECRET=
CLOUDINARY_UPLOAD_FOLDER=my-platform
```

The API secret must never be prefixed with `NEXT_PUBLIC_`.

---

## 7. Optional: enable email sending

The app works without an email provider.

When you want real contact replies and newsletter broadcasts, configure Resend:

```text
RESEND_API_KEY=
RESEND_FROM_EMAIL=
```

Use a sender address/domain accepted by your email provider.

The broadcast interface intentionally refuses to pretend that an email was sent when Resend is not configured.

## 8. Deploy to Netlify

### 8.1 Import the GitHub repository

Open Netlify and choose **Add new project → Import an existing project**. Connect GitHub, choose the repository, and let Netlify detect the Next.js framework. The repository includes `netlify.toml` only to pin Node 24 and the build command; no separate Netlify Next.js adapter package is required.

The current Netlify integration supports the Next.js App Router, SSR, Server Actions, Route Handlers, image optimization, and Middleware/Proxy behavior through OpenNext.

### 8.2 Environment variables

Add the environment variables from the next section under **Project configuration → Environment variables**. Netlify makes them available during the build and at runtime for serverless functionality. Do not commit secret values to GitHub.

### 8.3 Environment variables

Add the following variables before the production deployment:

```text
NEXT_PUBLIC_FIREBASE_API_KEY
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN
NEXT_PUBLIC_FIREBASE_PROJECT_ID
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID
NEXT_PUBLIC_FIREBASE_APP_ID

FIREBASE_CLIENT_EMAIL
FIREBASE_PRIVATE_KEY

ADMIN_EMAIL

NEXT_PUBLIC_APP_URL
NEXT_PUBLIC_SITE_NAME
NEXT_PUBLIC_SITE_TAGLINE

NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME
CLOUDINARY_API_KEY
CLOUDINARY_API_SECRET
CLOUDINARY_UPLOAD_FOLDER

RESEND_API_KEY
RESEND_FROM_EMAIL
RESEND_TO_EMAIL

CRON_SECRET
```

You can leave the optional email/cron values empty until you actually use those capabilities.

### 8.4 `NEXT_PUBLIC_APP_URL`

At first, set it to your actual Netlify URL, for example:

```text
https://your-project.netlify.app
```

After adding a custom domain, change the variable to the final canonical URL and redeploy.

## 9. Connect your custom domain

You can connect a domain purchased through Namecheap, Name.com, or another registrar. Netlify's Free plan currently supports custom domains with automatic managed HTTPS certificates.

Recommended sequence:

1. Deploy the Netlify site first and confirm the `*.netlify.app` URL works.
2. In Netlify, open **Domain management → Production domains → Add a domain → Add a domain you already own**.
3. Enter your custom domain and choose either Netlify DNS or your existing DNS provider.
4. If you keep DNS at the registrar, follow Netlify's exact DNS records shown in the **Pending DNS verification** area.
5. Netlify automatically provisions and renews its managed HTTPS certificate once the domain is correctly pointed.
6. Set the custom domain as the primary domain.
7. Change `NEXT_PUBLIC_APP_URL` to the final canonical HTTPS URL and redeploy.

For external DNS, Netlify documents an A record for the apex domain or an ALIAS/ANAME/flattened CNAME where supported, plus a CNAME for `www`. The exact records shown inside your Netlify dashboard take precedence over generic examples because they are customized for your site.

### About the GitHub Student Developer Pack domain

As of October 1, 2026, GitHub Education lists a Namecheap offer for **one year of .me domain registration** and also lists Name.com and .TECH domain offers. The student-pack benefit is tied to the eligible GitHub Education account and partner offer terms. Your sister should redeem it only in a way permitted by those partner terms; the website itself does not care which registrar owns the domain.

If the resulting domain is registered through Namecheap or another registrar, you simply connect that domain to the Netlify site using the DNS process above.

## 13. How media uploads work

Admin file flow:

1. Dashboard requests a signed upload signature from the server.
2. Server checks admin session.
3. Server signs the Cloudinary upload parameters.
4. Browser uploads directly to Cloudinary.
5. Browser sends the returned metadata to the server.
6. Firestore stores the media metadata.

This avoids sending large binary files through the Next.js server and keeps the Cloudinary API secret server-side.

## 16. What you should expect from the free tiers

### Firebase Auth
Suitable for a small personal/business site, with documented free quotas for authentication operations.

### Firestore
Firebase still provides a daily free quota for Firestore reads/writes/storage usage. A normal small personal site is unlikely to stress those limits immediately, but analytics can become the fastest-growing write stream.

### Firebase Storage
Not used by this project. Current Firebase storage changes require the Blaze billing plan for Cloud Storage usage.

### Cloudinary
The current free plan is useful for getting started. Monitor the credit allowance if you upload lots of high-resolution images, videos, or perform many transformations.

### Netlify
Netlify currently documents a $0 Free plan with custom domains + SSL, Functions, global CDN, and Git-based deployment. Netlify staff have also confirmed the Free tier may be used for commercial projects, while the legal Free Usage Tier remains discretionary and can be shut down if Netlify considers a project unsuitable for the tier. Keep usage within the current 300-credit monthly allowance and revisit the paid tiers as traffic grows.

## 17. Troubleshooting

### Dashboard redirects back to login
Check:

- `ADMIN_EMAIL` exactly matches the Firebase user's email;
- Firebase Admin credentials are correct;
- the Netlify deployment has the current environment variables;
- the user can authenticate successfully.

Redeploy after changing server-side environment variables.

### Google login fails
Check:

- Google provider is enabled in Firebase Authentication;
- the Netlify hostname is in Firebase Authentication authorized domains;
- the Firebase Auth domain in the web configuration is correct.

### File upload says Cloudinary is not configured
Check all four Cloudinary variables in Netlify and redeploy.

### Site settings are falling back to defaults
This usually means the site-settings document has not been seeded yet, or Firebase Admin configuration is not working. Run `/seed` after confirming the admin login.

### Contact/newsletter endpoint returns 429
The public endpoints have basic anti-abuse rate limiting. This is expected behavior when repeated requests arrive inside the configured window.

### Newsletter broadcast is unavailable
Add `RESEND_API_KEY` and `RESEND_FROM_EMAIL` and verify the sending identity with Resend.

The intended workflow is:

**Content/settings change:** use the dashboard.
